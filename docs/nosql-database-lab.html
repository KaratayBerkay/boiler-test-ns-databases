ns-databases · a reproducible boilerplate

NoSQL Database Lab

One deterministic e-commerce dataset (the same values as the relational lab rd-databases) loaded into every engine, then a shared operation catalog timed against each: point & batch reads, writes, partial updates, atomic increments, compare-and-set, range / secondary / nested / array queries, top-N, offset vs keyset pagination, group-by and time-bucket aggregation, joins, graph traversal, full-text, geo radius, vector kNN, multi-document transactions and TTL. An operation an engine has no way to express is marked n/a; one that fails at run time ERR.

Generated from results/<engine>/latest.json. p50 = client-observed median latency (monotonic clock, warm cache, ≥10 iterations after 2 warm-ups, result-set checksum recorded). Throughput figures use forked multi-process workers. Numbers come from one 28-core / 125 GB host with every container on that machine; some engines were measured with light cross-engine CPU contention (re-run serially with scripts/run-all.sh for publication-grade numbers).
